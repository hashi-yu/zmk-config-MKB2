# 薙刀式 v18 調査

## 結論

現在の Karabiner 設定は、説明名と有効ルールから見ると **薙刀式 v16 快速版を基礎にした設定**である。独自配列に合わせて入力キーコードを変更しているため、公式 v16 の無改造版ではない。

公式 v18 トップ版は、v17 から見ると「め」と「ね」の交換だけで、編集モードは v17 と同一である。一方、現在の v16 ベースから v18 へ移行する場合は、v17 で行われた変更も含むため、Space シフト面の3位置と、編集モードを使う場合の2項目が移行対象になる。

## 現在の実装

選択中の Karabiner プロファイル `New profile` では、次が有効になっている。

- `A1: 薙刀式v16《同時連続シフト拡張》`
- `B: 薙刀式配列v16（快速版）`
- `C1: 薙刀式《左右シフトかな拡張》`

次は無効である。

- `A2: 薙刀式v13以降《編集モード簡便化》`
- `C2: 薙刀式《エンター同時押しシフト拡張》`

現在の Space シフト面における対象4文字は、`~/.config/karabiner/karabiner.json` で次のように定義されている。

| Spaceとの組み合わせ | 現在の出力 |
|---|---|
| `Space + W` | ぬ |
| `Space + R` | め |
| `Space + B` | む |
| `Space + ,` | ね |

## 公式の更新履歴

### v16 快速版

作者の v16 発表では、v16 の主な変更としてマイナーかなの微調整、ヴァ行の変更、編集モードの縦横共用化が説明されている。

出典: [【薙刀式】v16快速版発表](https://oookaworks.seesaa.net/article/509198141.html)

### v17 ベスト版

作者は v17 の配列変更を「ぬ」「む」「ね」「め」の4文字と説明している。記事本文から確認できる v17 の配置は次の通り。

| Spaceとの組み合わせ | v17 |
|---|---|
| `Space + W` | め |
| `Space + R` | ね |
| `Space + B` | ぬ |
| `Space + ,` | む |

同じ発表で、編集モードについて次の変更も明記されている。

- 2面右手の「選択7」を中段へ移動
- `.`位置に「一行選択」を追加

出典: [【薙刀式】v17ベスト版、発表。](https://oookaworks.seesaa.net/article/519707171.html)

### v18 トップ版

作者は v18 について、v17 の「め」と「ね」を交換しただけであり、編集モードは同じだと明記している。理由は、より使用頻度の高い「め」をR裏へ置くためである。また、公式のワンショット漢直は v18 を前提とする。

したがって v18 の対象4文字は次の配置になる。

| Spaceとの組み合わせ | v18 |
|---|---|
| `Space + W` | ね |
| `Space + R` | め |
| `Space + B` | ぬ |
| `Space + ,` | む |

出典: [【薙刀式】v18トップ版、発表。](https://oookaworks.seesaa.net/article/521080503.html)

## 現在の v16 ベースから v18 への実変更

現在の設定と公式 v18 を比較すると、変更が必要なのは次の3位置である。

| キー | 現在 | v18 | 変更 |
|---|---|---|---|
| `Space + W` | ぬ | ね | 必要 |
| `Space + R` | め | め | 不要 |
| `Space + B` | む | ぬ | 必要 |
| `Space + ,` | ね | む | 必要 |

これはA1の同時連続Spaceシフト経路だけでなく、Bの快速版にある通常のSpaceシフト状態、C1の物理Shift拡張など、同じ文字配置を複製している全経路で一貫して変更する必要がある。出力ローマ字だけを交換するのではなく、説明、同時押し、Shift経路を同じ配置に揃えなければならない。

編集モードについては、現在A2が無効なので、通常使用時への影響はない。将来A2またはZMK側の編集モードを有効にするなら、v17由来の「選択7」と「一行選択」を反映する必要がある。

## 独自配列への影響

現在の物理・論理配列はQWERTYから次のように変更されている。

- QWERTYの `U` 位置からは `Backspace` が届く
- QWERTYの `;` 位置からは `U` が届く

今回のv18差分は `W`、`R`、`B`、`,` のSpaceシフト配置なので、この独自の `U`／`;`交換とは直接衝突しない。ただし、v18全定義を新規に取り込む場合は、すでに行った入力側の補正を失わないことが必要である。

## 既存のZMK v18ブランチ

このリポジトリには `feature/zmk-naginata-v18` ブランチがすでに存在する。そこには次が含まれている。

- `eswai/zmk-naginata` の固定コミット `6d852bf9b42d860b8a2bfbb0042dd20124c53ade`
- Naginata用レイヤー
- Home Row ModifierとNaginata SpaceのカスタムC behavior
- 独自配列のBackspace／U位置補正
- Naginata用回帰ケースと左右UF2

参照実装: [eswai/zmk-naginata](https://github.com/eswai/zmk-naginata/tree/6d852bf9b42d860b8a2bfbb0042dd20124c53ade)

ただし、このブランチは現在の `feat/latest` とは分岐しており、現在のSpace・Num・Arr・MT2変更を含まない。そのため、ブランチをそのまま切り替えるのではなく、v18実装部分を現在の構成へ移植し、最新のSpace動作と統合する必要がある。

## 検証済み事実と未検証事項

### 検証済み

- 現在有効なKarabiner本体はv16表記である。
- 現在の4文字配置は `W=ぬ`、`R=め`、`B=む`、`,=ね` である。
- v17で4文字が再配置された。
- v18はv17から「め」「ね」だけを交換し、編集モードはv17と同じである。
- 現在からv18へのかな配置差分は実質3位置である。

### 実装前に確認が必要

- 更新対象をKarabinerだけにするか、ZMK本体へ薙刀式を移すか。
- 既存 `feature/zmk-naginata-v18` のカスタムbehaviorを現在のSpace/MT2仕様とどう統合するか。
- 編集モードを引き続き無効にするか、v18相当として有効化するか。
